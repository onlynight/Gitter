# i18n 多语言框架（docs/i18n.md）

> 目标：中 / 英双语，中性语言（兜底回退）= **英文**，默认语言 = **英文**，设置页可切换，**切换立即生效（热切换）**。
> 采用 .NET 最通用的 **resx + ResourceManager + 卫星程序集** 方案（不采用 WinUI 原生 resw/MRT）。
>
> **状态：已落地（2026-10-05）**。全部 UI 字符串迁移完毕，全解决方案编译 0 警告、全量单测通过。
> 与方案的三处偏差（均已在实施中验证）：
> 1. 资源源改为单一 `Strings.tsv`（key + en + zh 三列）+ `scripts/gen-localization.ps1` 生成两份 resx 与 Designer——手工维护 resx 对 300+ key 极易失步，TSV 是唯一编辑入口，生成器同时校验 key 唯一 / zh 全覆盖 / 占位符一致；
> 2. `GitUI.Shell` 不引 Core（DependencyCheckTests 架构守卫）——`BashLocator` 改返回结构化错误 `BashLocateError(Kind, Detail)`，文案转译在终端页完成，Shell 层保持语言中立；
> 3. 默认英文后旧设置（无 language 字段）会切到英文——用户可在设置页显式选回"跟随系统/简体中文"。

## 一、选型理由

- 本项目 UI 几乎全部由 C# 代码构建（`MainWindow.xaml` 0 处文本，仅 `SettingsPage.xaml` 有少量字面量），resw 的 `x:Uid` 优势用不上，且会引入第二套资源体系。
- resx 生成强类型访问器（`Strings.Xxx`），key 拼写错误编译期即报；resw 走 `ResourceLoader.GetString("key")` 全靠字符串。
- `GitUI.Core` 是依赖根（被 App / Controls / ViewModels / Git / Diff 引用），resx 放 Core 一处即可全项目共享。
- 与 `tests/` 现有测试设施兼容，key 完整性可做成单元测试。

## 二、资源架构

```
src/GitUI.Core/Resources/
  Strings.tsv              ← 唯一手工编辑源：key \t 英文 \t 中文（# 开头为注释）
  Strings.resx             ← 生成产物（英文，中性文化）
  Strings.zh-Hans.resx     ← 生成产物（简体中文卫星资源）
  Strings.Designer.cs      ← 生成产物（强类型访问器）
scripts/gen-localization.ps1   ← 生成器（同时校验 key 唯一 / 占位符一致）
```

- **编辑流程**：改 `Strings.tsv` → 跑 `scripts/gen-localization.ps1` 重新生成三份产物 → 编译。
- key 命名：区域前缀 + PascalCase（`Log.TooltipRefresh` → `Strings.Log_TooltipRefresh`）；参数用 `{0}` 占位符。
- csproj：Core 设 `<NeutralLanguage>en</NeutralLanguage>`；App 设 `<SatelliteResourceLanguages>en;zh-Hans</SatelliteResourceLanguages>` 控制 publish 卫星语言集合。

## 三、语言服务

- `GitUI.Core/Settings/LanguageService.cs`：
  - `LanguagePreference { System, English, SimplifiedChinese }`，settings.json 存 `"system" / "en" / "zh-Hans"`（字符串常量同 `TerminalShellKind` 约定），大小写不敏感，未知值回退。
  - `Apply()` 热切换三件事：`Strings.Culture` 进程级资源查找覆盖（任意线程取值即时切换）、`DefaultThreadCurrent*`（新线程种子）+ 当前线程文化（日期/数字格式）、广播 `Applied`；`System` 档清除全部覆盖。
  - zh-CN 等 → zh-Hans 回退链由 ResourceManager 自动完成。
- 接入点：`App.OnLaunched` 启动时调用一次；设置页切换语言时即时调用。

## 四、生效时机与切换（热切换）

- **切换立即生效**，无需重启。机制镜像主题切换的广播模式：
  1. `LanguageService.Apply` 设置 `Strings.Culture`（进程级资源覆盖，VM 线程池续体的取值也即时切换）+ 线程文化，广播 `Applied`；**"跟随系统"档恢复类型初始化时捕获的系统文化快照**（线程文化被显式设置后 .NET 无"清除"API，必须记底稿，否则界面卡在上一语言）；
  2. 每个 MainWindow 订阅 `Applied`，经自身 `DispatcherQueue` 回投（广播在发起窗口的 UI 线程触发）后执行 `OnLanguageApplied`：**分步隔离刷新**（`RunLanguageStep`，单步异常记入 `%APPDATA%\GitUI\recoverable.log`，不拖垮其余步骤）→ chrome（导航/标题栏/命令面板框体/状态条）→ 依次调用缓存页的 `OnLanguageChanged()`（重设工具条按钮/占位符/自动化名，Log 页另经 `LogViewModel.RefreshRows()` 按新文化重建行与分组标题，分支页经 `RefreshAsync()` 重建组头）→ 刷新窗口标题；
  3. VM 生成的动态文案（状态条/横幅/一次性消息）本就在每次 Rebind 时经 `Strings.*` 取值，切换后自动跟随；
  4. 设置页每次导航重建 + 订阅 `settings.Changed`；**`Language_Click` 的顺序是先 `Apply` 再 `Update/Save`**——反了会让设置页在旧文化下渲染（表现为"切走再切回页面才变成新语言"）；命令面板若开着直接关闭（重开时按新语言重建条目）。
- 终端页会话状态由字符串改为 `TermState` 枚举存储、`UpdateStatus` 时转译，切换后状态条重译；空态失败文案同样按失败种类重译。
- 窗口关闭时 `App.Closing → window.DetachLanguageHandler()` 解除静态事件订阅，避免已关窗口被钉住。
- 诊断：`scripts/diag-language-hotswitch.ps1` 端到端验证 zh→en→跟随系统→zh 四步（UIA 驱动真实窗口）。

## 五、特殊处理（易踩坑点）

1. **命令面板最近命令**：历史版本以标题文本作 key，多语言后匹配失效 → 存储改用稳定 command id，显示时查表。
2. **日期/相对时间**：外化为格式模板资源（`Relative.DaysAgo`、`WeekdayNames`、分组头模板），不逐词硬编码。
3. **英文复数**：轻量方案，代码分支 `count == 1 ? Strings.X_One : Strings.X_Many`。
4. **UIA 冒烟依赖元素 Name 文本**：冒烟脚本断言需固定语言或双语适配。
5. git 错误消息中用户可见部分本地化，纯诊断 detail 不动；包显示名暂用包 id。

## 六、不本地化的内容

git 输出解析、shell/ConPTY 序列、`crash.log` 标签、诊断/调试文本、SVG path、主题包内部结构。
