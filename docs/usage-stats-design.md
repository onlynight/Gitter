## 零、问题陈述

Gitter 已经把用量数据聚合得相当完整，但唯一入口是设置页里的一张朴素 `<table>` 区块：

```
设置 → 模型 → Settings_UsageSection
  汇总（turn 数 2318）  输入 41.2M tok · 输出 5.8M tok · 缓存命中 32.6M tok · 估算费用 $14.83
  ┌ 按天 ─────────────────────────────┐
  │ 2026-10-13 │ 41 │ 1.82M │ 244k │ … │   ← 无趋势、无对比、无钻取
  │ 2026-10-12 │ 63 │ 4.06M │ 512k │ … │
  └───────────────────────────────────┘
  ┌ 按模型 ┐ ┌ 按任务（最近 20）┐
```

三个具体问题：

1. **回答不了问题**。用户想问的是「我这个月花了多少、哪个模型最烧钱、哪几天异常」，而现有 UI 只给一张需要自己心算的长表。没有「较上一周期」的对比，没有趋势形状。
2. **位置错配**。用量是决策信息（该不该换模型、该不该限制某类任务），不是配置项。埋在设置页 `models` 分类里，与「API Key 配置」同层，实际到达率为零。
3. **无法钻取**。`byTask` 只显示最近 20 条，且无跳转 —— 看到一笔 $1.94 的开销，无法一键到对应会话查原因。

## 一、现状盘点（设计依据）

### 1.1 已有的聚合引擎

`app/src/services/agents/usage.ts`（182 行，纯函数，**零写入**）扫描 `<repo>/.git/gitter/agent-tasks.json` 账本 + `agent-sessions/<taskId>.json` 的 `usageHistory`，聚合为三维报表：

```ts
export interface UsageReport {
  repoPaths: string[];
  totals: { turns; inputTokens; outputTokens; cacheReadTokens; cost: number | null };
  byDay:   UsageDayRow[];   // 按日升序，无上限
  byModel: UsageModelRow[]; // 按输入 token 降序
  byTask:  UsageTaskRow[];  // 按 lastActiveAt 降序，无分页
  emptyRepos: string[];     // 未跑过 agent 任务的仓库
}
```

成本口径：`cost = input/1e6 × inputPerM + output/1e6 × outputPerM`，四舍五入到 4 位（`round`）。**档案无 pricing 时 cost 为 `null`**（非 0）；缓存命中不计费。

### 1.2 关键约束（决定设计边界）

| 约束 | 来源 | 设计后果 |
|---|---|---|
| `cost` 可为 `null` | `usage.ts:69-72` `costOf` | 必须显示 `—`，**绝不显示 0**；`—` 行需视觉降权而非报错 |
| 无 `quota` 概念 | 全仓 grep 无 quota/限额，只有上下文 `budget` | **不做配额进度条**。只展示估算费用 + 趋势 |
| RPC 只有 `allProjects` 一个参数 | `bridge.ts:713` | 「7/30/90/全部」时间范围**必须前端切片** `byDay`，不能加参数 |
| `byTask` 无分页 | `usage.ts:174` 全量返回 | 页面单页上限 100，超出需显式标注（见 §5.2） |
| 无 repo 维度聚合 | `repoPaths` 仅数组回显 | 不能按仓库拆分；只能展示「N 仓库覆盖」+ `emptyRepos` |
| echarts 不可用于页面 | `gitui.lib.chart` 只存在于 iframe 预览文档内（`self.GITTER_CHART`），宿主文档零执行 | **图表必须手绘 SVG/CSS**，不引入图表库 |
| `usage` 图标已存在 | `web/src/pages/taskIcons.tsx:65` `usage` path | 侧栏图标直接复用，无需新增 |

### 1.3 可直接复用的资产

- **数字格式化**：`AgentOpsSettings.tsx:20-27` 的 `fmtTok`（B/M/k 分级）与 `fmtCost`（`n===null → "—"`）逐字复用，不改口径。
- **上下文明细范式**：`TaskComposer.tsx:410-458` 的 DeepSeek 式统计栏（`comp-stats-bar` 4px 槽 + `--c-border` 底 + `--c-text3` 填充）——本设计用它做 token 构成条。
- **卡片外壳**：`web/src/styles.css` 的 `.settings-section`（`--c-panel` 底 + `--c-border` + `--radius-md`）与 `.settings-row`。
- **页面注册**：`PageKey` 是裸 `string`（`store.ts:7`），新增顶层页**不需改枚举**；侧栏身份来自包 manifest 元数据（见 `gitui.page.tasks/manifest.json`）。

## 四、概览视图（第一屏 = 结论）

### 4.1 页头（作用域 + 时间范围 + 刷新）

```
┌──────────────────────────────────────────────────────────────────────┐
│ 用量统计  agent.usage.report                     [作用域] [范围] [刷新] │
└──────────────────────────────────────────────────────────────────────┘
```

- **作用域 chip**：显示当前仓库名 + `仅当前仓库` 小标；点击切「含全部项目」（对应 `allProjects: true`）。这是现有 UI 的复选框升级。
- **时间范围** `7 天 / 30 天 / 90 天 / 全部`：默认 30。**纯前端切片** —— `byDay` 已全量返回，`slice(-N)` 即可；KPI 与趋势同源同窗口，切一次全页联动。
- **刷新**：重发 `agent.usage.report`。无自动轮询（聚合要扫磁盘，成本不低）。

### 4.2 KPI 行：五个结论数

```
┌────────────┐ ┌────────────┐ ┌────────────┐ ┌────────────┐ ┌────────────┐
│ 估算费用    │ │ 输入 TOKEN  │ │ 输出 TOKEN  │ │ 缓存命中    │ │ 任务/模型  │
│ $14.83     │ │ 41.2M      │ │ 5.8M       │ │ 32.6M      │ │ 96 / 4     │
│ ▲22% 较上期 │ │ 2318 轮 ▲18│ │ 均2.5k/轮  │ │ 79.1% 12断点│ │ 4 仓库覆盖 │
│            │ │            │ │ ▲31%       │ │            │ │ 0 空账本   │
└────────────┘ └────────────┘ └────────────┘ └────────────┘ └────────────┘
```

规格：

| 元素 | 规格 |
|---|---|
| 标签 | 10.5px / 600 / `--c-text3` / uppercase / `letter-spacing:.6px`，前置 12px SVG 图标 |
| 数值 | **21px / 600** / `--c-text` / `tabular-nums`；单位 `M/k` 降为 12px `--c-text3` mono |
| 无值 | 21px 降至 19px，整值取 `--c-text3`（不显示红） |
| 副行 | 11px / `--c-text3`；涨跌用 `▲` + `--c-green`，无涨跌信息时留空不占位 |
| 告警 | `--c-amber`，仅用于「缓存断点」这类解释性数字 |

**环比口径**：`本期窗口 sum ÷ 上期同长窗口 sum − 1`。上期无数据（首次使用）→ 隐藏整行 meta，不显示 `▲0%`。

`— ≠ 0`：若 `totals.cost === null`（无任何档案配价），费用 KPI 显示 `—` 且副行改为 `3 个档案未配置单价`。

### 4.3 Token 构成条

KPI 下方一条 5px 三段构成条，把「输入/缓存命中/输出」的比例一眼看清：

```
输入 ████████████████████  (灰)
缓存命中 ██████████████       (浅灰，叠在输入段内)
输出 ██▌                      (蓝 = 唯一彩色强调)
```

**三阶灰而非彩虹**是本页的色彩纪律：`--c-text3`（输入）/ 45% 透明（缓存）/ `--c-link`（输出）。蓝是全应用唯一的彩色语义（`theme.gitui.acrylic` 的 `Accent` 在深/浅主题都是近单色 `#EAEAEA`/`#1B1B1B`，只有 `--c-link #6BABF5` 是彩色），用它标记「真正生成的内容」，其余全是上下文供给。

规格：

- **画布**：`<svg viewBox="0 0 760 168">`，`preserveAspectRatio="none"` 宽自适应；`padding: L34 R38 T10 B20`（右留 38 给费用右轴）。
- **柱组**：每槽宽 `iw/30 ≈ 22.7px`，主柱宽 `slot×0.52`（最小 3px），输出条 `sub = barW/3.4` 贴主柱右缘。
- **网格**：4 档水平虚线 `stroke-dasharray:2 4` `opacity:.65`；左轴 token（`--c-text3`），右轴费用（`--c-amber`）。
- **费用折线**：`stroke-width:1.25` `stroke-dasharray:3 2` 虚线，点 r=2 隔日抽样 —— 虚线+细线避免与柱组抢注意力，同时保住趋势形状。
- **x 轴**：每 5 天一个标签（`9/15 9/20 …`），加最后一天，共 7 个。
- **hit area**：每槽一个 `fill:transparent` 全高矩形承接 `mouseenter`，比精确悬停柱更宽容。
- **Tooltip**：绝对定位在 `.trend-wrap` 内，`--solid` 底 + `blur(16px)` + `--sh2`；内容 = 日期（mono）/ 轮次 / 输入 / 输出 / 缓存命中+命中率 / 费用（分隔线后，amber 高亮）。横向 clamp 在容器内。
- **指标切换**：点「输入/缓存命中/输出/费用」任一可显隐，`off` 态 `opacity:.4`。至少保留 1 项可见（全灭时不做特判，空图即可，符合数据为空时的诚实呈现）。
- **Y 轴自动缩放**：`max(input)×1.12`，费用 `max×1.25`。**不强制从 0 开始**（趋势页惯例，保留起伏可读性）；但柱底始终贴基线。

- 行网格 `26px | 1fr | auto`：序号（mono `--c-text3`）/ 名称+条 / 数值+占比。

- `—` 用 `.na` 灰字 + 弱化字重，与已计费行形成对比但不报错。

- **最近活跃**：相对时间（`2 分钟前` / `昨天 21:14` / `10-10 22:08`），三档递减，`--c-text3` mono。
- **行交互**：hover `--c-panel`；点击 → `navigate("tasks")` 并选中对应 `taskId`。

### 5.3 筛选

页头分段切换 `全部 / 已计费 / 失败`。纯前端过滤 —— `byTask` 已全量返回，过滤不触发 RPC。

## 十、数据契约（零新增）

**复用现有 RPC，无签名变更：**

```ts
// app/src/bridge.ts:713 —— 完全沿用
call<UsageReport>("agent.usage.report", { allProjects: false })
```

**时间范围 = 前端切片（关键决策）：**

```ts
function windowSlice(rep: UsageReport, days: number /* 0 = 全部 */) {
  const dayRows = days === 0 ? rep.byDay : rep.byDay.slice(-days);
  // KPI / 趋势 / 模型分布 / 表格全部由 dayRows + byTask 过滤窗口内的 lastActiveAt 重算
  // 环比窗口 = 紧邻的前一个等长区间
}
```

> 权衡：`byTask` 是按 `lastActiveAt` 降序的，窗口过滤需在窗口上界截断。`byModel`/`totals` 服务端按全量给出，前端窗口视图需从 `byDay` 反推 —— **但 `byDay` 没有按模型拆分**，所以严格说窗口内的「模型分布」无法精确算出。
>
> **v1 裁决**：模型分布与任务明细展示**全量**口径（在卡片标题标注「全量」），仅 KPI 与趋势随窗口变化。这是当前数据模型的硬限制，列为 §十二 开放问题 1。

**可选增强（v2，非本稿范围）**：`agent.usage.report({ allProjects, since?, until?, taskId? })` 支持服务端窗口与分页，可解锁精确的窗口内模型分布 + 任务分页。

## 十二、开放问题

1. **窗口内的模型分布无法精确计算。** `byDay` 不含 `byModel` 拆分，切到「7 天」时右栏模型分布只能显示全量口径。
   *倾向：v1 标注「全量」并在卡片副标说明；v2 通过扩展 RPC 的 `since/until` 参数由服务端重算。理由：诚实标注的成本远低于引入服务端参数，且模型排名的相对顺序在短期窗口内通常稳定。*

2. **`Settings_UsageSection` 词条缺失。** `app/resources/packages/gitui.page.settings/i18n/zh-Hans.json` 只有 `Nav_Settings` 一个键，设置页当前实际渲染的是 key 原文。
   *倾向：新增用量页时一并补齐该 section 的词条。理由：既然要动这块，顺手修掉比留着一个显示 key 原文的 section 更便宜。*

3. **失败任务是否应该计入「估算费用」？** 当前 `usage.ts` 按 `usageHistory` 逐条计费，失败任务已消耗的真实 token 全额计入（示意数据中 12 个失败任务 = $0.42）。
   *倾向：全额计入但在汇总条单独标出失败部分（本稿已做）。理由：token 已经烧掉了，隐藏它会让用户高估 ROI；单独标注则保留洞察价值。*

4. **缓存断点数从哪来？** `byDay`/`byTask` 不含断点数，`cacheBreaks` 只在 `agent.context.stats`（**单任务实时**，且随任务结束消失）。KPI 第 4 卡的「12 断点」在 v1 无数据源。
   *倾向：v1 从 `UsageEntry.note`（压缩/换模型/重启续跑/模式切换注记）计数得到近似值 —— 会话文件 v2 已存 `note` 字段，只是 `usage.ts` 未聚合。需要在 `usage.ts` 加一个 `cacheBreaks` 计数，属**最小改动**（纯聚合层，不动存储）。理由：这是本页唯一的跨任务洞察，值得为它加 5 行聚合代码。*

5. **表格单页上限。** `byTask` 无分页，本稿取 100 并显式标注「超出需扩展 RPC 分页」。
   *倾向：暂不加分页参数。理由：96 个任务已是常见上限的 1.5 倍，真实需求出现前先不加接口面。*
