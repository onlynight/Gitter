危险区

Revert 提交

将创建一个新提交来自动撤销以下提交的改动，历史完整保留：
4409455 fix(monaco): F1 命令面板修复——quick input 双缺陷源码级补丁
→ 3 个文件的反向改动将出现在变更页（已暂存），提交信息预填「Revert "…"」。
① 菜单插入位置：现有 commit 右键菜单（LogPage.tsx:384-403）中，「从该提交创建分支…」之后、「Reset/Reflog/比较」分组之前，自成分隔区；每项带 mono 灰字 hint 标注语义。
② Revert 不标红，Reset 标红：Revert = git revert 生成反向提交，不动既有历史，是非破坏性操作；真正危险的是既有「Reset 分支到此…」（改写历史）——本稿顺带把它移入「危险区」小标题 + 红色（现状无标红，语义应拉开）。
③ Revert 确认框：默认不勾「立即提交」——反向改动进变更页（等价 revert --no-commit 后的暂存态），提交信息预填 Revert "原提交信息"，用户在变更页确认后提交，多一道反悔机会；勾选则直接 git revert --no-edit 一步到位。确认键用蓝色主键（非 danger 红）——安全操作不吓唬人。
④ Cherry-pick：git cherry-pick <sha> 拣选到当前分支；点击直接执行 + toast（可撤：冲突时中止即可）。选中提交 = 当前分支顶端时该项禁用置灰（顶端提交拣选无意义，改信息走 amend，见变更页设计稿）。多选连续拣选随将来多选功能再加。
⑤ 冲突接续：revert / cherry-pick 遇冲突，冲突助手（ConflictAssist）横幅已有这两种状态的识别（gitops.ts:33-34），但继续/中止按钮当前未接线（bug 清单第 1 条）——实现时需补 git.revertAbort/Continue、git.cherryPickAbort/Continue 四个 RPC 并放开 ConflictAssist.tsx:93 的分支条件，与本功能一并交付。
⑥ 后端：新增 RPC commits.revert（sha, commitNow）、commits.cherryPick（sha），服务层放 gitbranches.ts 或 gitops.ts（与冲突态同处更内聚）。
试玩：点提交行呼出菜单 → 「Revert 此提交…」看确认框（切换勾选看效果行变化）→ 确认出 toast；「Cherry-pick 到当前分支」直接出 toast；Esc 关闭菜单/弹窗。
