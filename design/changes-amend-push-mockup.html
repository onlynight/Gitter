强制推送

将用本地 dev 覆盖远端 origin/dev。 以下远端提交会被移出分支（对象仍在远端 reflog，但常规操作不可达）：
0f0af88 fix(shell): 侧栏折叠/展开动画恢复
使用 --force-with-lease：若远端有你本地没有的新提交，推送会被拒绝并提示先拉取，不会盲覆盖。
① amend 勾选项：放提交操作行最左（GitHub Desktop 同位），pill 样式勾选态亮蓝边。勾选 = git commit --amend：提交框预填上次提交信息（可改）、按钮文案「提交」→「修改提交」、「提交并推送」同样生效、汇总行改「将并入上次提交」；取消勾选一切还原（不丢用户已输入内容——预填前先存原稿）。
② 已推送警告：勾选时若 HEAD 已在远端（现有 ahead/behind 信息即可判定），textarea 下方出 amber 警告条（对齐 .banner 样式）说明需强推，不阻断；本地未推送的提交勾选安静无警告。
③ Push 拆分图标钮：工具栏同步区全面图标化（Fetch / Pull ▾ / Push，与 stash、discard 设计稿同一套 26px 图标钮）；Push 左半 = 推送（行为不变，高频零成本），右半 chevron = 菜单向下弹（工具栏贴页顶）。菜单项带灰色命令说明副行：「推送 tags」= git push origin --tags；顺序高频在上。
④ 强制推送：红色项 + 分隔线居底；必须过 danger 确认框，列明将被移出的远端提交（origin/dev..dev 的远端独有提交 = 覆盖面）；固定用 --force-with-lease（远端有他人新提交时拒绝并报错，走错误横幅提示先拉取）。仅本地领先时菜单项可用，否则禁用置灰。
⑤ 后端：amend 扩展现有 changes.commit（amend 标志）；push 扩展 forceWithLease / tags 参数；强推确认框数据取自现有 log 查询（本地与远端分叉提交），零新表。
试玩：勾「修改上次提交」看预填/文案/警告条变化 → 再取消还原；点「Push ▾」开菜单 → 「强制推送…」看确认框 → 确认出 toast。
