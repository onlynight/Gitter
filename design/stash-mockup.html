应用时若与工作区冲突：该 stash 条目保留不删，冲突文件落入变更页，走冲突助手解决。
① 入口与承载：变更页工具栏同步区全面图标化（Fetch / Pull ▾ / Push），Push 右侧新增「Stash」收件箱图标钮（26px，与相邻图标钮同规格；右上角圆点角标显示条数 >0 时，tooltip 带数量；打开对话框后刷新）。承载选对话框而非独立页面/侧栏：stash 是暂态操作面（存→走人，回→取走），不值得占导航位；列表＋行内操作＋展开文件需要宽度与滚动，popover 装不下——对齐现有 ReflogDialog 的 620px 列表对话框模式（kit/ReflogDialog.tsx），实现为 kit/StashDialog。
② 保存：对话框顶部一行 = 消息输入（可选，默认「WIP on <分支>」）＋「暂存修改」主键，等价 git stash push -m（含未跟踪文件，-u）；成功后变更页文件区清空、角标 +1。工作区无变更时按钮禁用。
③ 恢复（unstash）：行悬停/选中出操作——「应用并删除」= git stash pop（默认推荐），「仅应用」= git stash apply（保留条目，想多地复用时用）。冲突语义按 git：pop 遇冲突时条目不会被删，冲突文件落变更页走冲突助手——底部灰字固定说明，消除「东西丢了吗」的疑虑。
④ 展开预览：行首 chevron 展开该条涉及的文件清单（git stash show --include-untracked --name-only），辅助决定「应用还是删掉」。
⑤ 删除：单条「删除」= git stash drop，红色 danger 描边钮（mis-click 有 reflog 可救但不承诺）；不做「清空全部」入口——safety.ts 已把 stash clear 列为危险命令拦截，UI 侧同样不提供。
⑥ 空态：无 stash 时列表区显示「没有 stash」居中灰字（同 ReflogDialog 空态）。
⑦ 后端：新增 RPC stash.list / stash.push / stash.pop / stash.apply / stash.drop / stash.show（服务层新文件 gitstash.ts，全部走 gitexec）；stash@{n} 序号展示用 list 顺序推导，不长期持有句柄。
试玩：点工具栏「Stash」图标钮（收件箱）开对话框 → 填消息点「暂存修改」（工作区清空、角标 +1）→ 行悬停「应用并删除」把文件放回变更页（角标 −1）→ 点 chevron 展开文件 → Esc / ✕ 关闭。
