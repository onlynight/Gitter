# S1 · 领域模型与 Git 读取层

## 目标
无 UI 的可运行产物 + 可自动执行的验证手段。按设计文档 §8 S1：不可变模型、`IRepositoryService`、libgit2sharp 实现、`GitWorker` 队列、`GitFixtureBuilder`、≥20 个不同拓扑集成测试、并发测试、1 万提交性能基准。

## 环境结论（已实测，写进计划的关键事实）
- **libgit2sharp 0.32.0**，NuGet 还原成功，本机 native 加载正常。
- **0.3x API 与常见教程差异极大**，全部实测确认：
  - `Repository.Init(path, isBare)` 返回 **`string`（git 目录路径）**，不是 `Repository`。需 `new Repository(gitDir)` 再拿句柄。
  - **没有** `Repository.WorkingDirectory`，改用 `repo.Info.WorkingDirectory`（注意带尾 `/`）。
  - **没有** `repo.Status()`，改用 `repo.RetrieveStatus(StatusOptions)` → `RepositoryStatus`。
  - `repo.Commit(msg, author, committer, options)` **必须 4 参**。
  - `new Signature(name, email)` 编译不过 —— `Signature` 构造器强制要求 `DateTimeOffset`。所有签名必须 `new Signature(name, email, DateTimeOffset)`。这是最阴的一个坑：`git.Status()` 等不存在的成员会被解析成类型表达式，报错信息完全误导。
  - `TreeEntry.Target` 是 `GitObject`，需转 `Blob`；`Blob.GetContentStream()` 拿字节。
  - `repo.Reset` 是实例方法，不是扩展方法。
- git CLI 2.55 可用，`commit-tree` / `mktree` / `update-ref` 正常。

## 接口设计

```csharp
public interface IRepositoryService
{
    string Open(string path);            // 校验路径，返回规范化工作目录
    string HeadSha(string workDir);
    IReadOnlyList<BranchRef> GetBranches(string workDir);
    LogPage GetLog(string workDir, LogFilter filter);   // 分页 + 过滤
    CommitNode GetCommit(string workDir, string sha);
    IReadOnlyList<TreeEntry> GetTree(string workDir, string treeish);
    IReadOnlyList<DiffResult> GetCommitDiff(string workDir, string sha);  // 该提交的树对比
    DiffResult GetFileDiff(string workDir, string path, string aSha, string bSha);
    IReadOnlyList<WorktreeFileStatus> GetStatus(string workDir);          // 三层分类
    IReadOnlyList<DiffHunk> ComputeDiff(string oldText, string newText);
}
```

设计要点：
- **所有方法接收路径字符串**，内部 `using` 打开仓库、用完即弃。这是 §3.2 的核心约束：libgit2 `Repository` 句柄不可跨线程。
- `GetLog` 分页：`filter.Limit` 默认 50，`Skip` 起始偏移；`TotalCount` 用 `Commits.Count()` 一次算好，`HasMore = Skip + Items.Count < TotalCount`。
- 过滤用 libgit2 的 `CommitFilterCriteria`（Author / MessagePattern / CommitTimeSpan / RefName），在 rev-list 层做而不是拉全量再筛 —— 10 万提交仓库的前提。
- `GetStatus` 三层分类映射：
  - `IsStagedOnly` → **Staged**
  - `IsModifiedInWorkdir` 且不在 index → **Changes**
  - `IsNewInWorkdir` 且 `NewInIndex == false` → **Unversioned**
  - `IsDeletedInWorkdir` → **Changes**
  - `IsInConflict` 单列（v1 归入 Changes，标注冲突）
- `ComputeDiff`（纯字符串 → `DiffHunk[]`）放在 Git 项目里实现 Myers 的**简化行级**版本（LCS 动态规划），S2 再用 DiffPkg 替换为字级引擎。这样 S1 就能给 `GetFileDiff` 提供输出，也让 S2 有可替换的接缝。S1 明确标注这是临时实现，不追求 S2 的黄金用例精度。

## GitWorker 队列设计

```csharp
public sealed class GitWorker : IDisposable
{
    public GitWorker(IRepositoryService service);
    public Task<T> Invoke<T>(Func<IRepositoryService, T> action, TimeSpan? timeout = null);
    public Task<T> Invoke<T>(GitRequest<T> request);
}
```
- `BlockingCollection<GitRequestBase>`，`BoundedCapacity` 有界（默认 1000）避免内存爆。
- 单 worker 线程循环 `Take()`，`Execute` 内 `try/catch` 把异常 `SetException` 到 TCS，绝不静默吞。
- `Dispose()` 走 `CompleteAdding()` + `GetConsumingEnumerable()` 收尾 + `Thread.Join(5s)`。
- **测试覆盖**：100 个请求并发入队、异常传播、Dispose 后拒收、有界队列阻塞、无死锁（10s 超时守卫）。

## GitFixtureBuilder（用 git CLI 构造拓扑）

设计文档明确要"用 `git commit-tree` 手工构造特定拓扑"。CLI 走 `Process`，隔离 `HOME` 避免污染全局配置：

```csharp
public sealed class GitFixtureBuilder : IDisposable
{
    public static GitFixtureBuilder Init(string path, string defaultBranch = "main");
    public string Commit(string message, params (string file, string content)[] files);
    public string Branch(string name, string fromSha);
    public string MergeCommit(string name, string baseSha, string headSha, out IReadOnlyList<string> conflicts);
    public string CherryPick(string srcSha, string ontoSha);
    public void Checkout(string name);
    public void WriteWorktree(string file, string content);   // 制造未提交变更
    public void Stage(string file);
    public void DeleteWorktree(string file);
    public string Sha(string rev);
}
```
- 随机化器 `RandomizedFixtureGenerator(Rng seed)` 生成 20 个拓扑，覆盖：线性链、双分支、三方合并、快进、cherry-pick、多分支扇出、深层嵌套、孤立提交、空提交、大文件、中文文件名、嵌套目录。
- 测试用 `[IClassFixture]` + `IDisposable` 保证临时目录清理。

## 风险与对策

| 风险 | 对策 |
|---|---|
| libgit2sharp 0.3x API 与文档不符 | 已实测全部签名，写死在本计划里 |
| `Repository` 句柄跨线程崩溃 | 所有 service 方法内部开合，`GitWorker` 强制串行 |
| git CLI 在 Windows 下 `core.autocrlf` 影响 blob 内容 | fixture 统一 `git config core.autocrlf false` |
| 测试间状态污染 | 每个 fixture 独立临时目录 + `IDisposable` 清理 + 隔离 HOME |
| 1 万提交基准在本机可能超 500ms | 先用 1 万跑，不达标就分两档（1 万/10 万）并记录实测值，不硬凑阈值 |
| `TreatWarningsAsErrors=true` 导致新增代码编译失败 | 每步跑 `dotnet build` 确认 |
